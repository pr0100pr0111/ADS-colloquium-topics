# Билеты к устному командному коллоквиуму по АиСД

## 🏛 Архитектура билета

Каждый билет в директории `topics/` имеет строгую, стандартизированную структуру. Архитектура специально оптимизирована под формат **устного командного ответа**: от быстрого введения спикера за 30 секунд до парирования каверзных вопросов экзаменатора и строгих доказательств.

### 1. Метаданные билета (`ticket`)
* Поддерживает параметр `speaker: "Имя Фамилия"` — позволяет закрепить ответственного докладчика от команды прямо в шапке PDF.

### 2. Блиц-выжимка (`#quick`)
* **Цель**: ответ за первые 30 секунд.
* Самая суть темы: определение, идея метода, временная и пространственная сложность. Незаменимо, если нужно быстро освежить память перед выходом к доске или подхватить ответ сокомандника.

### 3. Логика работы (`= Логика работы`)
* Пошаговый алгоритм (нумерованный список 1..5).
* Строгие определения (`#definition(name: [...])[...]`).
* Инварианты цикла/структуры.
* Наглядные трассировки и примеры с таблицами (`#example`, `#ptable`).

### 4. Сложность и свойства (`= Сложность и свойства`)
* **Сводная карточка `#facts(...)`**: ключевая матрица характеристик:
  - *Время*: лучший / средний / худший случаи.
  - *Память*: вспомогательная память, глубина стека, in-place.
  - *Структура данных*: требования к памяти и представлению.
  - *Ограничения и нюансы*: устойчивость (stability), константы, применимость.
* Формулировки теорем и лемм (`#theorem`, `#lemma`, `#proposition`, `#remark`).

### 5. Реализация (`= Код`)
* Эталонная реализация на C++ в блоке `#listing(caption: [...])[...]`.
* Код лаконичен, без лишней обвязки, с комментариями в критических местах (строгость сравнений, границы циклов, работа с указателями).

### 6. Вопросы экзаменатора (`= Вопросы экзаменатора`)
Двухуровневая подготовка к диалогу с преподавателем в формате таблицы пар вопрос–ответ (`#qa(...)`):
* `*Обязательные.*` — базовые вопросы на знание определений, инвариантов и асимптотики.
* `*С подвохом.*` — каверзные вопросы на тонкости (граничные случаи, ложные предположения, нетривиальные примеры).

### 7. Доказательства и глубина (`#appendix`)
* Строгие математические доказательства (`#proof`), развороты рекуррентностей, индукционные переходы.
* **Скрывается в обычном режиме** и отображается **только в полном режиме** (при флаге `--input full=1`). Это позволяет держать базовый конспект сжатым (на 1–2 листа для печати), сохраняя полную версию со всеми выкладками.

## 🛠 Компиляция билетов

Для сборки требуется установленный компилятор [Typst](https://github.com/typst/typst) (`typst >= 0.11`).

> **Важно**: параметр `--root .` обязателен при запуске из корня проекта, чтобы Typst имел доступ к общей библиотеке стилей `lib/style.typ`.

### 1. Компиляция одного билета

* **Базовая версия** (компактная шпаргалка без аппендикса):
  ```bash
  typst compile --root . topics/01_time_complexity.typ build/01.pdf
  ```

* **Полная версия** (с подробными доказательствами из `#appendix`):
  ```bash
  typst compile --root . --input full=1 topics/01_time_complexity.typ build/01_full.pdf
  ```

* **Режим отслеживания (live preview / auto-compile при сохранении)**:
  ```bash
  typst watch --root . topics/01_time_complexity.typ build/01.pdf
  ```

---

### 2. Сборка всех билетов сразу

#### Базовые версии всех билетов:
```bash
mkdir -p build && for f in topics/*.typ; do
  num=$(basename "$f" | cut -d'_' -f1)
  typst compile --root . "$f" "build/${num}.pdf"
done
```

#### Полные версии всех билетов (с доказательствами):
```bash
mkdir -p build && for f in topics/*.typ; do
  num=$(basename "$f" | cut -d'_' -f1)
  typst compile --root . --input full=1 "$f" "build/${num}_full.pdf"
done
```
